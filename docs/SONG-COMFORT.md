# Климат, сиденья и руль Song

Кнопки климата и сидений открывают `ComfortView` внутри правой панели через общую анимацию настроек/техники. Закрытие возвращает встроенное приложение. Активная страница восстанавливается после пересоздания Activity; оформление использует текущую дневную/ночную тему.

Страница сидений использует исходные WebP салона и подсветки из установленного на Song `com.byd.airconditioning`, без изменений изображений. Инструмент `tools/import_song_comfort_assets.py APK` повторяет импорт и переводит кривые штатных Lottie-значков в Android VectorDrawable. APK производителя в репозиторий не включается.

Управление вынесено за контур кузова. Для каждого переднего сиденья один полупрозрачный блок: сверху подогрев, снизу вентиляция, между ними разделитель. Линии соединяют блоки с сиденьями и кнопку руля с рулём; у кнопки зеркал/заднего стекла линии нет. Цикл сидений: **выключено → 2 → 1 → выключено**; удержание выключает. Руль и зеркала/заднее стекло переключаются вкл/выкл. Задние сиденья показаны как часть штатной графики, управления ими нет.

`ComfortPanelBridge` запускается через существующее локальное ADB. Адреса Ac/Setting и типы устройств берутся из SDK текущей прошивки. Климат отправляет штатные пакетные `setIntArray` с источником UI; MAX использует одиночную запись, как `setAcMaxCoolingState` этой прошивки; при изменении температуры сохраняется единица измерения, прочие зоны имеют штатное значение «не менять» 0. Сиденья/руль используют существующий `ComfortCommandWriter`. UI-уровни 0/1/2 сидений соответствуют SDK 1/2/3. Неподдерживаемые значения, отсутствие данных и демо-режим блокируют управление.

Опрос работает только при открытой активной странице. Данные старше пяти секунд считаются недоступными. Команда отправляется только при явном нажатии; подтверждение требует совпадения фактического состояния. После нажатия UI сразу показывает выбранное значение; подтверждение идёт в фоне. При отказе или отсутствии подтверждения применяется свежий фактический снимок и показывается короткий Toast.

Проверка 20.10.2026 на физическом Song / DiLink 5.0: чтение Ac/Setting, доступность пакетного API и всех необходимых символов, отображение исходной графики, расположение кнопок и области нажатия. Сборка, Android Lint и логические тесты проходят. Автоматические проверки не переключают физические функции; свидетельства сохранены в `artifacts/song-live-2026-10-20/`.

## Штатная страница климата

`ClimatePanelView` переносит оригинальную объёмную фигуру, дневную/ночную графику и потоки воздуха из того же OEM APK. Температуры расположены вертикально по краям: стрелки и соседние значения меняют температуру по одному шагу. Три штатных значка обдува переключают стекло, лицо и ноги; последнюю активную зону нельзя выключить в несуществующий режим 0. Снизу находятся DUAL, уменьшение/увеличение вентилятора и шкала из семи секторов 1–7; при скорости 0 все сектора пусты. Сверху — питание, AUTO, A/C, MAX, лобовое стекло, зеркала/заднее стекло, рециркуляция, вентиляция без охлаждения.

Потоки статичны: для каждого направления используется один исходный кадр. Периодической перерисовки и смешивания кадров нет. Активная подсветка показывается при свежих данных, включённом климате и ненулевом вентиляторе. Направления и выделение кнопок используют фактический снимок с временным оптимистическим значением для ожидающих команд. На Song подтверждено чтение дополнительных `AC_MAX_COOLING_STATE` и `AC_VENTILATION_STATE`; проверки не отправляют команды изменения климата.

Проверены сборка, Lint, ограничения и формирование команд MAX/вентиляции, все семь комбинаций обдува, 25 подписанных элементов управления с областью нажатия не меньше 48 dp. Снимок физического экрана: `artifacts/song-live-2026-10-20/climate-oem-page.png`.

Повторное нажатие на кнопку уже открытой страницы климата, сидений, настроек или статистики закрывает её с общей анимацией возврата к приложению. Нажатие на другую страницу переключает на неё. Активная вкладка в заголовке климата/сидений также закрывает страницу при повторном нажатии; программное открытие и восстановление состояния Activity остаются явным открытием.

Шкала вентилятора содержит ровно семь равных секторов с промежутками; при уровне N заполнены первые N секторов, при 7 заполнение доходит до правого края. Скорость 0 достигается уменьшением вентилятора до выключения. Актуальный снимок: `artifacts/song-live-2026-10-20/climate-static-sectors.png`.

## Мгновенная реакция

`ComfortController` хранится в контексте приложения, отдельно от страницы. Он опрашивает машину только при наличии видимой страницы, но завершает уже запрошенные команды после её закрытия. `ComfortRequests` накладывает выбранные значения поверх фактического снимка сразу, без блокировки всех кнопок. Повторные нажатия рассчитываются от отображаемого значения; для каждого поля очередь объединяет ожидающие изменения до последнего значения. Уже отправленная команда не отменяется, после неё применяется последний выбор.

Ответы привязаны к номеру запроса: старый результат не стирает более новый выбор. Ошибка последнего запроса убирает оптимистическое значение, показывает свежие данные машины и короткое сообщение; повторяющиеся ошибки не спамят Toast. При потере данных показывается недоступное состояние. Все прежние ограничения значений, проверка свежести и блокировка демо-режима сохранены. Проверки модели покрывают быстрый цикл сидений 2 → 1 → выкл, объединение команд, запоздалые ответы, откат и независимые поля.
