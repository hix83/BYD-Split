# Восстановление ADB на новых прошивках Song

Включено в выпуск Song 0.9.3.

Настройки → Система → Восстановление ADB после перезагрузки.
По умолчанию выключено. Для Android 11+ и прошивок, которые закрывают
ADB после перезагрузки; BYDMate описывает эту ситуацию как 2606+.
Номер 2602 сам по себе не определяет совместимость.

Пока обычный ADB доступен и ключ BYD Split уже разрешён, включите функцию.
Приложение получает для собственного пакета WRITE_SECURE_SETTINGS через
существующее shell-соединение. Статус подтверждает подготовку. Если ADB уже
закрыт, для первичной активации его нужно один раз включить обычным способом.
Этот механизм не заменяет первичную авторизацию.

При запуске приложения проверяется shell-команда на 127.0.0.1:5555.
Если порт недоступен, но подключён Wi-Fi, включается Android wireless debugging.
TLS-порт определяется через service.adb.tls.port или mDNS _adb-tls-connect._tcp.
Команда tcpip:5555 отправляется по STLS / TLS 1.3 с тем же RSA-ключом,
который используется существующим ADB-клиентом. Подключение ограничено
loopback, mDNS-объявления других устройств игнорируются. Успех определяется
реальной shell-командой на 5555, затем перезапускаются помощники ввода и руля.
EOF после tcpip не считается доказательством ошибки: проверяется фактическое
возвращение обычного ADB.

На новой Wi-Fi-сети подтвердите штатный диалог отладки на экране, затем
при необходимости нажмите «Повторить проверку / активацию». Автоматическое
подтверждение диалога из BYDMate здесь не перенесено. Проверка выполняется
раз в 20 с, пока жив процесс приложения. Запись, способная вызвать системный
диалог, ограничена интервалом 10 минут; ручная попытка снимает этот интервал.
После перезагрузки используется существующий автозапуск BYD Split. Если он
отключён, восстановление начнётся при ручном запуске приложения.
В деморежиме нет подключения, выдачи разрешений и изменения системной отладки.

Выключение переключателя отменяет дальнейшие шаги старой попытки и выключает
беспроводную отладку только если её ранее включила эта функция. Уже открытый
обычный порт 5555 не закрывается. Исходно включённая беспроводная отладка
остаётся включённой. Уже отправленную команду перезапуска adbd отозвать нельзя.

## Проверки и ограничения

JDK 17 / SDK 35: assembleDebug, lintDebug, testDebugUnitTest (NO-SOURCE),
tools/test_logic.sh. На Android 12 / API 32 прошёл AdbRecoveryInstrumentation:
сертификат с существующим ключом, проверка подписи, настоящий взаимный TLS 1.3
поверх STLS с тестовым локальным adbd, служба tcpip:5555, запрет TLS downgrade,
отбрасывание чужих адресов. Тест не переключает системный adbd эмулятора.

```powershell
.\gradlew.bat assembleDebug assembleDebugAndroidTest '-PtestRunner=ru.logunov.bydsplit.AdbRecoveryInstrumentation'
adb -s emulator-5554 install -r app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5554 install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s emulator-5554 shell am instrument -w ru.logunov.bydsplit.test/ru.logunov.bydsplit.AdbRecoveryInstrumentation
```

На физическом Song ещё нужны первичная подготовка, холодная загрузка,
подтверждение сети, реальный mDNS и восстановление помощников. Доступ к
системному свойству и выдача разрешения зависят от прошивки. Если встроенное
приложение не запустилось до восстановления ADB, может потребоваться повторно
выбрать его в панели: механизм повторного запуска панелей здесь не менялся.
