## Стирание

После ручного сканирования можно выбрать блок или все блоки с отображаемыми
кодами. Отчёт должен быть не старше 10 минут. Перед стиранием пользователь
подтверждает действие. Исходный JSON и полный текст сохраняются отдельно от
текущего отчёта; текст можно скопировать кнопкой в разделе результатов.
Хранится один последний исходный отчёт, следующее стирание заменяет его.

Помощник проверяет P, READY, достоверную скорость ровно 0, свободную диагностику
и отсутствие постороннего трафика. Для ранее проверенного Song L / DiLink5
сохраняется узкий профиль отсутствующего guard; для других машин его отсутствие
блокирует операцию. Один запрос ClearDiagnosticInformation 14 FF FF FF на блок,
без повторной отправки при таймауте. Положительный ответ 54 подтверждает команду,
но результат оценивается только вместе с повторным чтением кодов.

Подтверждено/отказ/неизвестно/не отправлено показываются раздельно. Если повторное
чтение не подтверждено, старые коды помечаются как данные до стирания. Неизвестный
результат блокирует повторное стирание до нового сканирования. Исходная дата
сканирования не обновляется у неперечитанных блоков. При аварийном завершении
сохранённые блокировки остаются. Активные неисправности могут вернуть код сразу.

Операция имеет бюджет 120 секунд, владелец — 130 секунд, помощник — 125 секунд.
Уход со страницы, выключение машины, потеря владельца, смена P/READY/скорости,
чужая диагностика или таймаут останавливают операцию и закрывают слушатель.
Никаких сервисов, периодических сканирований и перезапусков помощников не добавлено.
Демонстрационный режим меняет только пример, не отчёт реальной машины.

## Собственный Telegram-бот

1. Создать отдельного бота через @BotFather → /newbot.
2. В настройках Split открыть «Интеграции» → Telegram и вставить токен на ГУ.
3. Отправить выданный восьмизначный код боту (или /start КОД в группе).
4. Нажать «Проверить код», проверить название чата и подтвердить подключение.

Код живёт 10 минут; старые обновления, пересланные сообщения, каналы и сообщения
других ботов не подходят. При нескольких чатах нужно выпустить новый код.
Токен сохраняется только после подтверждения чата, зашифрован AES-GCM с ключом
Android Keystore. Не вставлять реальные токены в Git, документацию, логи или чат.
Для бота с webhook/другим получателем обновлений следует создать отдельного бота.

Отправка — кнопкой из диагностики. Дополнительно можно включить выключенную по
умолчанию отправку после ручной проверки/стирания. Это не запускает сканирование
в фоне. Отчёт содержит время, блоки, статусы кодов, доступные расшифровки, пробелы
в ответах и результаты стирания. VIN, координаты, журнал поездок, токены и сырые
логи не отправляются. Расшифровки остаются на языке исходного справочника с
указанием точного или похожего соответствия модели.

Короткий отчёт — текст; длинный — полный UTF-8 TXT, без обрезания. Запросы только
к Telegram Bot API по HTTPS, без перенаправлений, с ограничением времени/размера.
Нет фонового getUpdates, автоматических повторов и очереди. Сбой показывается
пользователю, сохранённый отчёт можно отправить позже. Уход со страницы и режим
сна отменяют текущую отправку. Если Telegram принял сообщение перед обрывом
связи, результат доставки может быть неизвестен; ручной повтор может дать дубль.

## Проверка и ограничения

Логика проверяется tools/test_logic.sh (включая DtcEraseEngineTest), Android API,
шифрование и отмена — DtcTelegramInstrumentation с подставным транспортом без
выхода в Telegram. DtcUiInstrumentation проверяет обе темы, подтверждение,
отмену, стирание примера и сохранность настоящего отчёта.

Стирание на Song L остаётся экспериментальным: полный цикл с достоверным
повторным чтением всех блоков не подтверждён. Реальный бот не подключён,
доставку в пользовательский Telegram нужно проверить после настройки на ГУ.
Не заявлять проверку сна закрытой машины по тестам эмулятора.

## Исправление расшифровок 06.11.2026

Сравнены DtcDescriptions/DtcBlockClass/DtcBlockNames и dtc/ в BYDMate 4.3.0
(84ac31a): данные расшифровок и правила не изменились относительно изученной 4.2.0.
Для проверенного профиля Song L DM-i в локальную models.tsv добавлено
соответствие AutoType 161 → 61402, где
manuals.tsv явно называет серию 宋L DM-i / DM. Это локальная адаптация Split,
а не утверждение, что такая привязка уже есть в BYDMate.

Новый подбор сохраняет приоритет блока и модели. Если в справочнике модели
не указан блок, описание допустимо лишь при одной уникальной паре исходного
китайского и английского текста для полного кода в этом справочнике. При
неизвестном типе блока и отсутствии точного совпадения допускается общее
значение, только когда все вхождения полного кода в базе имеют одинаковый
английский текст. Оно явно помечается общим значением без подтверждения блока.
Разные значения не объединяются и не выбираются произвольно. Ни адрес блока,
ни код ошибки не используются для выдумывания его идентичности.

В регрессии используется 10 примеров кодов: 8 имеют описание из справочника
Song L DM-i; B1C2A-00 и P1A3C-00 — однозначное общее значение BYD. Проверка
DtcDescriptionsTest использует настоящие таблицы, проверяет все 10 кодов,
конфликты и происхождение. В интерфейсе и полном тексте отчёта одинаковые
расшифровки и источники. Старый отчёт дополняется офлайн при открытии страницы;
его дата не обновляется, helper/CAN/автоматическая отправка не запускаются.

## Названия и сведения возникновения · 06.11.2026

В ручной скан добавлены read-only 22 F1 97 (собственное имя блока) и
19 04 <полный DTC> FF (стоп-кадр), по механике BYDMate 4.2/4.3.
Не более 30 стоп-кадров и 35 секунд на дополнительные сведения внутри прежнего
общего бюджета 90 секунд; уход со страницы/сон/потеря владельца останавливают
тот же помощник. Сбой в дополнительном чтении сохраняет завершённый список
кодов. Посторонний трафик прекращает дополнительные запросы. Запись, стирание,
смена диагностической сессии, security access и keep-alive не добавлены.

Название в отчёте: собственное имя F197 → подтверждённый тип F194 →
помеченная как предположение типовая карта BYDMate. Адрес сохраняется. Названия
по карте не считаются подтверждёнными идентификаторами Song и не влияют на
выбор расшифровки кода. IPB разворачивается как интегрированный блок тормозов.

На Song L проверено получение собственных имён и стоп-кадров. Части блоков
F197 недоступен. Само отсутствие ответа по типовому адресу не доказывает
физический обрыв или отсутствие узла.

Дата и пробег возникновения пока не подтверждены по DID, единицам, масштабу,
часовому поясу и первому/последнему событию. Сырые стоп-кадры сохраняются в
частном отчёте для последующего разбора. UI и текст раздельно показывают
полученный, но не расшифрованный кадр; отказ, неполный ответ или отсутствие
ответа. Дата сканирования остаётся отдельной величиной.

DtcMetadataTest проверяет строгий формат read-only запроса, привязку ответа к
полному коду, отказы и чужие ответы, сохранность кодов при сбое extras,
закрытие устройства, перевод F197 и явные предположения по адресам.
