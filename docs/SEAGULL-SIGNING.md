PKCS12, alias `seagull`, RSA 3072, SHA256withRSA, самоподписанный сертификат
сроком 10950 дней (30 лет).

Публичные сертификат и отпечаток: `signing/seagull-release-cert.pem`,

Архив содержит ключ И пароль в properties; он приватный, без дополнительного

Если ключ потерян, совместимые обновления с этой подписью выпускать нельзя.

## Подключить на другом ПК

Распаковать оба файла рядом, сохранив их имена:

```text
Windows: %USERPROFILE%/.byd-split/signing/
macOS:   ~/.byd-split/signing/

  seagull-release.p12
  keystore.properties
```

Не заменять существующий каталог без резервной копии его ключа.
Путь storeFile внутри properties относительный: одинаковые файлы подходят
обоим ПК. Пароли менять в проекте не требуется. Gradle ищет конфигурацию:

1. Файл по пути из `BYD_SIGNING_PROPERTIES`.
2. `keystore.properties` в корне проекта (игнорируется Git).
3. `~/.byd-split/signing/keystore.properties`.

С подключённым ключом **debug и release подписываются одинаково**.
Без него debug использует локальный Android debug-ключ для разработки,
а release завершается ошибкой. Неизвестный сертификат отклоняется.

```powershell
# Windows
.\gradlew.bat assembleRelease
```

```sh
# macOS
./gradlew assembleRelease
```

Результат: `app/build/outputs/apk/release/app-release.apk`.
Перед публикацией проверить `apksigner verify --print-certs <APK>`:
отпечаток должен совпадать с новым релизным сертификатом выше.
Увеличивать versionCode и соблюдать канал из docs/SEAGULL-UPDATES.md.

## Переход с существующего alpha.4

Публичный APK `seagull-v0.9.2-alpha.4` подписан старым ключом Mac:
`63442ad5ab88b867970e1d7480aa2e849ec46f63b20c61b2da837aa43d715d10`.
Новый ключ **не позволяет обновить этот APK поверх**. Самоподписанность
нормальна; несовместимость вызвана другим приватным ключом/сертификатом.

Первый переход требует отдельной миграции с проверенной резервной копией
настроек/данных и переустановкой. Удаление приложения обычно удаляет его
данные. В рамках создания ключа приложение на автомобиле не переустанавливалось.
План миграции и публикация нового выпуска ещё не выполнены.
После установки сборки с новым ключом будущие APK с тем же ключом и большим
versionCode смогут обновляться штатно, включая обновления из GitHub.

На Windows успешно собраны debug и release; apksigner проверил оба, отпечатки
совпадают с новым сертификатом. Версия пока alpha.4/code40, новый релиз
не опубликован: этот APK проверяет подпись и не заменяет уже выпущенный alpha.4.
Ранее установленные APK эмулятора с Windows debug-подписью также не обновятся
поверх новым ключом.

## Если понадобится сохранить совместимость со старым alpha.4

Владелец сможет позже предоставить `~/.android/debug.keystore` с другого ПК.
Скрипт импортирует именно старый ключ, не генерируя новый:

```sh
python3 tools/prepare-shared-signing.py --source /путь/к/старому/debug.keystore --output-dir ~/.byd-split/signing-alpha4
```

В Windows Python может запускаться через `python` или `py -3`.
Нужен keytool из JDK 17. По умолчанию alias `androiddebugkey`, пароль
запрашивается скрыто (Enter означает стандартный `android`). Другой alias:
`--source-alias`. BYD_SOURCE_STORE_PASSWORD и BYD_SOURCE_KEY_PASSWORD
позволяют передать пароли приватно через окружение.

Скрипт сверяет старый сертификат с публичным alpha.4, импортирует тот же ключ
в PKCS12 и создаёт новый пароль контейнера. Исходник не меняется, существующий
каталог не перезаписывается. Для сборки со старым ключом задать
`BYD_SIGNING_PROPERTIES` на `keystore.properties` каталога signing-alpha4.
Gradle разрешает оба известных сертификата; совпадение с подписью установленного
приложения проверять отдельно. Старый Mac-ключ пока не получен.

## Сборка, стенд и публикация одним ключом

Для обычной подготовки APK на macOS/POSIX:

```sh
./tools/build_release.sh
```

Скрипт запускает проверки логики, сборку и lint. Перед упаковкой проверяет
подпись по `signing/seagull-release-cert.sha256`, packageId, версию Seagull
и отсутствие debug-флага. Готовый APK и SHA256SUMS.txt находятся в
`dist/seagull-v<версия>/`. Этот каталог не включается в Git.

Скрипты `tools/install_and_start.sh SERIAL`, `tools/run_emulator_demo.sh` и
`tools/seagull-emulator.ps1 -InstallApp` используют `app-release.apk` и
проверяют новый релизный сертификат перед установкой. Они не удаляют старое
приложение при несовместимой подписи. Перед выбором SERIAL проверить реальные
ADB-подключения; старый адрес не используется как адрес по умолчанию.

Публикация из чистого коммита ветки seagull после увеличения версии/code:
создать тег текущей версии и отправить коммит/тег на GitHub, затем выполнить:

```sh
./tools/publish_release.sh docs/releases/<примечания-к-выпуску>.md
```

Публикация использует проверенный локальный release APK, сверяет SHA256
загруженного файла с GitHub и лишь затем публикует prerelease. Существующий
релиз не перезаписывается. CI debug APK без приватного ключа пригоден только
для проверки сборки; скрипт публикации такой APK не принимает.

На macOS 19 октября подключён профиль `~/.byd-split/signing` через ссылку
на предоставленный владельцем внешний каталог ключа. Пароли не дублируются
в проекте и не передаются в аргументах команд. Подпись проверяется после
синхронизации с сегодняшним коммитом GitHub, а не на устаревшей alpha.4-базе.
