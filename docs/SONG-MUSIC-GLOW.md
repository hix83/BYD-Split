# Светомузыка панели — первый вариант

Рабочая ветка после 0.9.2, не опубликовано.

Настройки → Экран и тема → Светомузыка панели. По умолчанию выключена.
Есть яркость 0–100% (по умолчанию 40%), высота волн 10–80% высоты панели
(по умолчанию 52%) и предпросмотр на 6 секунд без музыки.
Переключатель, яркость и высота сохраняются; изменения видны сразу.
В эмуляторе включено для проверки.

Выбор цвета: исходный сине-бирюзово-фиолетовый градиент, синий, бирюзовый,
фиолетовый, зелёный, янтарный, розовый и белый. Выбор применяется сразу и
сохраняется. Для одноцветных вариантов слои сохраняют небольшое различие
насыщенности и яркости одного оттенка, чтобы волны различались.
«Свой цвет» открывает выбор оттенка, насыщенности и светлоты, образец и ввод
#RRGGBB. Цвет волн меняется во время настройки; «Применить» сохраняет его,
«Отмена» или закрытие диалога возвращает прежний. Последний свой цвет
запоминается отдельно от готовых вариантов. Прозрачность по-прежнему
определяется общей настройкой яркости. Ввод HEX заменён выбором касанием;
в кнопке «Свой цвет» отображается цветной образец.

Эффект: три полупрозрачные сине-бирюзовые волны от нижнего края панели,
с плавным нарастанием и затуханием. Рисуется отдельным Canvas-слоем под
иконками; поддерживает классическую и динамическую панели. Геометрия кнопок
и обработка касаний не меняются. В редакторе эффект останавливается.

Источник — Android Visualizer, общий аудиовыход (session 0), waveform 256
отсчётов, до 15 обновлений/с, нормализованный уровень. Частота отрисовки
ограничена 30 кадрами/с; FFT, частицы, размытие и полноэкранные слои не используются.
Объекты Paint, Path и градиенты переиспользуются. На тишине цикл кадров
останавливается. Пауза освобождает Visualizer; фоновое приложение, скрытая
панель и выключение настройки также освобождают захват. Проверка активного
воспроизведения — AudioManager, USAGE_MEDIA / USAGE_GAME.

Android требует RECORD_AUDIO и MODIFY_AUDIO_SETTINGS для такого Visualizer.
Разрешение RECORD_AUDIO запрашивается при включении через системный диалог;
отказ оставляет функцию выключенной. AudioRecord и микрофон не используются,
аудио не сохраняется и никуда не отправляется. Если прошивка не разрешает
анализ общего выхода, настройка показывает соответствующий статус. Радио,
Bluetooth и другие источники DiLink требуют проверки на автомобиле.

## Проверки

Сборка assembleDebug, lintDebug, testDebugUnitTest (NO-SOURCE).
На Android 12 / API 32 MusicGlowInstrumentation проверяет энергию настоящего
PCM-сигнала через глобальный Visualizer, предел частоты кадров, освобождение
захвата после паузы, прекращение кадров на тишине, предпросмотр и остановку
при уходе в фон. В изолированном прогоне: peak=1.0, 72 кадра за 2.5 секунды
(28.8 кадра/с). Это не замер нагрузки на физическом Song.

```powershell
.\gradlew.bat assembleDebug assembleDebugAndroidTest '-PtestRunner=ru.logunov.bydsplit.MusicGlowInstrumentation'
adb -s emulator-5554 install -r app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5554 install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s emulator-5554 shell pm grant ru.logunov.bydsplit android.permission.RECORD_AUDIO
adb -s emulator-5554 shell am instrument -w ru.logunov.bydsplit.test/ru.logunov.bydsplit.MusicGlowInstrumentation
```

Тест воспроизводит сгенерированный тон и меняет настройки выделенного эмулятора.
Для проверки паузы другие приложения не должны проигрывать звук. Например,
окно входа Яндекса может держать собственный AAudio-поток; при нём захват
обоснованно остаётся активным. После теста яркость возвращается к 40%.
